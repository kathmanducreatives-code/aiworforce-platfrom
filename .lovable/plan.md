## Root cause (confirmed from live console)

The production bundle at `https://agentory.space` crashes on first execution with:

```text
Uncaught Error: supabaseUrl is required.
  at new SupabaseClient
```

`src/integrations/supabase/client.ts` reads `import.meta.env.VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY`. In dev/preview these come from `.env` so the app works. The published build (`agentory.space`, `resume-ace-ai-29.lovable.app`) ships without those values inlined, so `createClient(undefined, undefined, ...)` throws synchronously at module-import time — before React mounts, before any error boundary can catch it. Result: permanent black screen.

The file’s own header says it’s auto-generated by Lovable and the canonical version hardcodes the URL and publishable key as string literals. It was modified to use env vars, which is what broke production.

## Fix (minimal, no app behavior change)

### 1. Restore `src/integrations/supabase/client.ts` to hardcoded literals
Replace the env-var reads with the project’s actual values so the bundle is self-sufficient:

```ts
const SUPABASE_URL = "https://wqnigjhcwjxtmordrwno.supabase.co";
const SUPABASE_PUBLISHABLE_KEY = "eyJhbGciOi...GelbMIlFnirbVFu50ywoFekbHSBcg_v2hc3dIVHMPog";
```

(Both values are public/anon — safe to commit. This matches Lovable’s standard generated client.) This alone unblocks production.

### 2. Defensive guard in `client.ts`
If either constant ever becomes empty in the future, throw a clearly-labelled error (caught by AppErrorBoundary) instead of Supabase’s opaque message — so we never silently re-introduce a blank screen.

### 3. Pre-React fallback marker in `index.html`
Add a tiny inline “Loading Agentory…” block inside `#root` plus a 10-second watchdog script that, if React hasn’t replaced it, swaps in a visible message with Reload / Sign out buttons. This guarantees the domain can never render a fully black screen again, even if a future bundle fails to execute.

### 4. Wrap `<App/>` in `AppErrorBoundary` at the root
`src/main.tsx` currently renders `<App/>` directly. `AppErrorBoundary` exists inside `App.tsx` but cannot catch crashes that occur during `App`’s own import/render. Move/duplicate the boundary into `main.tsx` so it catches any future top-level boot crash and shows the existing fallback UI.

### 5. Verify on the live domain after publish
After the user clicks Publish → Update:
- Reload `agentory.space`, `agentory.space/dashboard` (direct + refresh), confirm app renders and no console error.
- Sign in flow returns to `agentory.space`.
- Pilot responds to “hello”, Daily Brief works, Execution Plan Card renders for a search query.
