## Defects and what they need

1. **Compiler (blocks rollout): the extra legacy fields beside a correct understanding.**
   - Under v3, `applyUnderstanding` (`missionUnderstanding.ts`) writes the understanding into the mission. It then keeps the model's free-form `hard_constraints`. `missionCriteria.ts` compiles any of those whose words appear in the request into a hard `constraint`, or an `exclusion` for a negative operator.
   - **Root cause not yet pinned to exact fields.** This study recorded only each answer's `understanding`, not the legacy fields that produced the extra criterion.
   - The obvious guesses ("excluded_roles: SDRs", "business_type: insurance agencies") already compile correctly today (checked), so a fix written now would be guesswork.
   - The harness now records the **whole answer** and the **exact extra criteria** (`proposal`, `extraHard`), and classifies every failure itself.
   - The next study run gives the exact fields; the fix follows from them.
2. **Model: clarification instead of the contract's default readings (24).**
   - The contract instructions need explicit defaults for:
     - "in the US/States" (HQ, per M03/M13/M15);
     - an unstated funding window ("recently" / "lately");
     - growth words.
   - Whether "in the States" should mean HQ or presence is an **owner product decision** already taken in the corpus (HQ). The model disagrees often enough that it should be restated in the instructions.
3. **Model: M20 "growing the sales team" (owner rule 2026-11-03: headcount growth, not hiring).** This is wrong on all 3 repeats, and it is the collapsed contrast. It needs a contract instruction with this example.
4. **Transport: `incomplete_response` at 4,000 output tokens (1.8 %).**
   - Production uses the **same ceiling** (`gptMissionModel.ts`, `maxTokens: gen.maxTokens ?? 4000`).
   - Mission compilation does not go through the Luna → Terra escalation module, so in production this is a failed compile.
   - Candidate fix: raise the ceiling for the v3 schema, or retry once with a larger one. This needs a cost decision, because the worst case per call grows.
