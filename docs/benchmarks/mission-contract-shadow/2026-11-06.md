# Mission Contract v4 shadow baseline (offline, $0), 2026-11-06

**Produced by:** `deno run --allow-read --allow-write --allow-env scripts/dev/mission-contract-shadow.ts --out docs/benchmarks/mission-contract-shadow`

**Raw data:** `2026-11-06.json`. Rows hold case ids and meaning keys only, never request text.

## What is compared

For every corpus phrasing, and for every recorded live answer of study run #24, two readings are compared with `compareContracts`, as production chat's shadow mode would record them:

- **baseline:** the mission the production compiler builds from the answer, converted by the compatibility boundary;
- **candidate:** the v4 contract built from the same answer.

The run #24 answers number 163 in total. One recorded answer (M07, repeat 3) is a genuine clarification question: v3 refuses to compile it, so it appears as an error row and is never guessed.

## Reading

- **v3 → v4: nothing is added, strengthened or weakened, and no approval changes.** Every hard-plan difference is M17's raw-text "saas" duplicate, the approved difference recorded in `tests/fixtures/mission-reliability/v1/v4-expectations.json`.
- **The removals are invented or unrepresentable items that v3 compiled and v4 does not.** Among them:
  - `industry: businesses` (5), `industry: us` and `industry: cos`;
  - `signal_logic` restated as a constraint (6);
  - malformed `employee_range` restatements (7);
  - the B2B audience word, which is a preference under the audience policy;
  - the M17 duplicate.
- **v1 → v4 differs much more, as expected.** v1 is the production compiler today. Most of the difference is hiring-role detail (`changed`), plus geography and signals that v1 inferred as preferences and that v4 reads as required where the user stated them.

The release thresholds that apply these numbers to production shadow traffic are in `docs/architecture/mission-contract-rollout.md` §6.
