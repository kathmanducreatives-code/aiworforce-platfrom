# R1.2: ORION acceptance fixes (stabilization)

- **Base:** R1.1 (`pilot-chat` at `a1633f45`, live).
- **Scope:** `pilot-chat` only. No frontend change, no migration, no secret change, no data write.
- **Evidence:** a read-only audit of production on 2026-11-16 (chat metadata, edge logs, schema, row counts) and the owner's 12 manual acceptance areas.

## 1. Findings and root causes

| # | Finding | Verdict | Root cause (exact) |
|---|---|---|---|
| 1 | Executive brief labelled as a LinkedIn and campaign draft (15:11:34); the internal management report routed correctly (08:11:32) | **Defect** | `draftKindsFor` matched format words inside a negation: "…an internal analysis report, **not a LinkedIn post, email, marketing draft or campaign**". Because draft kinds were present, `isInternalAnalysis` was false and every compose request drafted. The 08:11 report named no formats, so it worked. |
| 2 | An Apify plus LinkedIn execution request was refused, but got a "LinkedIn message" Draft Only chip (08:14:00) | **Defect** | The draft check ran **before** the "do not execute" check, and "**send** each founder a LinkedIn message" matched the `linkedin_message` format. The model then refused correctly, but `metadata.orion_draft` was already set, so the chip showed. |
| 3 | ORION sees totals for 37 signals but no row-level signals | **Defect** | `retrieveEvidence` ranks all evidence and then cuts at **50 across sources**. Production's 61 leads are "agent inference" (rank 2); all 37 signals are "unverified" (rank 3: no verification level, status `unverified`). So the top 50 were all leads and **zero signals ever reached ORION**: every evidence panel in the session was 8 leads. Separately, no bounded row-level signal listing existed. |
| 4 | A compound follow-up answered partly or not at all (15:26:26) | **Defect** | `orionRoute` sent any read with a back-reference ("these companies") to the scoped list template ("Those 8: …"), even when it asked for judgement. Neither question was answered. |
| 4b | "Second company you just selected" was blocked (15:19:58) | **Correct behaviour** | ORION's previous answer said the three companies were tied ("None can defensibly be selected"). Asking which one is right. |
| 4c | Follow-up referents | **Latent defect** | Referents were the 8 default `[E#]` lead subjects, not the companies the answer discussed. "The second one" would have meant Newton Software. |
| 5 | Eight ATLAS leads attached to a Company Brain audit and to own-company content | **Defect** | `selectEvidenceForQuestion` always filled up to 8 items from the pool. A topic signal named "buyer-intent" also matched "buyer roles" through first-word matching. |
| 6 | Dates | **Defect (labels)** | A lead's `created_at` (when ATLAS saved it) was presented alongside hiring claims, and the model called it "observed". A signal with no event date was dated by its observation, implying an age. Ages counted elapsed 24-hour periods, not calendar days. |
| — | Data limitations, not defects | **Incomplete data** | In production: 35 of 37 signals have no event date; the 21 hiring and 2 funding signals have no source URL; 14 market and competitor signals are topics, not companies; no signal carries a verification level. R1.2 reports these fields as "not recorded" / "not stored". |

## 3. Changes (`pilot-chat` and its shared modules)

| File | Change | Finding |
|---|---|---|
| `_shared/orionIntelligence.ts` | `withoutNegatedClauses()`: formats and internal-analysis words are read with negated clauses removed. | 1 |
| | `isExecutionRequest()`: send, publish, schedule, scrape, enrich, Apify, "find N", "save them" or "message each" is execution; it is drafted only when an explicit "draft/write a <format>" is present. The "do not execute" and execution checks now precede drafting. | 2 |
| | A back-referencing read that needs reasoning goes to ORION's answer (a plain drill-down keeps the scoped read). New "judgement" reasoning signal: "should I…", "can I safely…", "supported only by…", "which claims…". | 4 |
| `_shared/evidence/retrieve.ts` | Opt-in `perSourceLimit`: each source is capped separately, so leads can't crowd out signals. Default behaviour is unchanged for other callers. | 3 |
| `_shared/orionWorkspaceFacts.ts` | A bounded **LISA SIGNAL TABLE** (≤ 60 rows, this workspace only, only for signal questions). Each row shows type, company or topic, observed date and age, event date or "not recorded", source URL or "not stored", and verification level or "none recorded". Rows are cited as `[S#]` and their ids recorded. | 3 |
| | `calendarDaysBetween()` (UTC calendar days). Named companies are kept in the order the question names them. | 6, 4c |
| `_shared/orionEvidenceContext.ts` | **Relevance gate:** no lead or signal evidence unless the question names a company or is about leads, signals, pipeline or evidence. Source choice ignores negated clauses. First-word name matching applies to company-style names only. | 5 |
| | **Date labels:** "ATLAS saved this lead on … ; when the hiring was observed is not recorded"; "observed …; event date not recorded — the event is at least N days old". Ages use calendar days. | 6 |
| | `presentedSubjectsFor()`: follow-up referents are the named companies, then the `[E#]` subjects the reply cites (handles `[E1–E8]` and `[E2]–[E4]`). | 4c |
| | **Answer shape:** `[S#]` citations, date rules, and the meaning of "not recorded". | 3, 6 |
| `pilot-chat/index.ts` | Uses `presentedSubjectsFor` for referents and records `signal_table_ids`. | 3, 4c |

**Not changed:**
- **Off limits:** the frontend, migrations, secrets and the Company Brain. Delegation stays off and no paid path is touched.
- **Release tooling:** `deploy-r11-pilot-chat.sh` now also accepts R1.1 (`a1633f45`) as the live "before" build. TEST tooling gains `run-r11.ts --suite r12` (14 acceptance turns with R1.2-specific checks), and the one-command TEST run runs both suites.

## 4. Risk and rollback

- **Risk: low.** One function changes, there are no data or schema changes, and spend controls and OpenAI-only routing are unchanged.
- **Evidence:** behaviour now differs where it was wrong. Brain and own-company questions show no evidence panel; signal questions show signals.
- **Prompt size:** larger only for signal questions (≤ 60 table rows, about 2k input tokens, about $0.001).
- **Rollback:** `deploy-r11-pilot-chat.sh --rollback --backup release-backups/r11-<UTC>` redeploys the backed-up R1.1 `pilot-chat` (`a1633f45`).
