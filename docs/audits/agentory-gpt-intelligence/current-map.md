## Model routing is two systems, not user-selectable multi-model AI

The lead spine uses direct OpenAI Chat Completions through `gptProvider` with
`gptModelRouter` stage policies: **gpt-5.6-luna** primary, **gpt-5.6-terra** on
specified validator repair paths, Sol excluded from normal routes. Some stage
names deliberately throw `DeterministicStageError`. Router entries are policy,
not proof that every stage runs in every mission.

Shared `aiProvider.TASK_MODELS` uses **claude-haiku-4-5-20251001** for chat,
orchestration, execution and Brain. Only tool-input planning/helper permit
**gpt-4.1-mini** fallback. Gemini references in old comments/UI do not
constitute an active direct Gemini text adapter. Existing leadStrategy adapter
files include an older Lovable/OpenAI-compatible boundary; inspect their actual
selected path, not the presence of that URL, before asserting a live provider.

The machine-readable [call-site scan](evidence/model-call-sites.json) lists
direct facade calls and factory wiring with exact lines. It is a syntactic
cross-check, not a per-mission count, full call graph or assertion that imports
execute. The table above gives the runtime meaning. SDK/gateway availability and
per-account model entitlements are UNVERIFIED; model-call mocks prove contracts,
not quality.

## Existing adaptive feedback is not absent

`sequentialSourceBridge` already calls `sourceFeedbackRuntime` and the adaptive
lead runtime. This is a bounded, explicitly flag-and-workspace-allowlist-gated
model feedback path over source observations and the permitted action menu. Its
ledger counts HTTP requests, validates proposals and falls back to the code
source transition when a proposal is unusable. Current deployment enablement is
UNVERIFIED. It is a strategy feedback loop, not permission to rewrite Company
Brain or a demonstrated learning system from customer call outcomes. Reuse and
measure it before building another next-action model.

## Agent names and actual collaboration

`LEGACY_SLUG_TO_VISUAL` maps scout → **Lyra**, aria/hawk → **Atlas**, penn →
**Mira**, scribe → **Orion**. Pilot is a separate coordinator. “Mirea” is not
the canonical current visual key. Public role/model labels do not select
execution.

Lyra reuses lead/signal discovery and monitored research; Atlas reuses
enrichment, verification and qualification; Mira reuses opener/outreach/content
drafting; Orion's scribe mapping is writing/content work, not proof of a
separate autonomous operations planner. Pilot/orchestrate/task dependencies
coordinate the pipeline. `run-agent` can display separate agent completion
messages after one lead run; that does not establish independent agents
deliberating or checking one another.

Useful collaboration is already possible as task results with IDs, sources,
dependencies and blocked reasons. Improve these handoffs before adding agents.
One research task requesting a missing source and one writer consuming its
validated result is valuable; several models repeating the same evidence verdict
adds cost and correlated confidence without new information.
